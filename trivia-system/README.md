# 📞 מערכת הצבעות וטריוויה טלפונית חכמה

מערכת מלאה להצבעות חיות, טריוויה וסקרים דרך הטלפון (**ימות המשיח**) עם תצוגת תוצאות חיה באחוזים, שופטים עם טווח ציונים אישי, הארכות זמן בזמן אמת ועוד.

```
מחייגים ──► ימות המשיח (שלוחת API) ──► Cloudflare Worker ──► Supabase (PostgreSQL)
                                            ▲
             דפי הניהול / שליטה / צפייה / שופטים (מוגשים מאותו Worker)
```

- **Supabase** = מאגר נתונים בלבד. המפתח נמסר פעם אחת כסוד ל-Cloudflare וזהו — אף דפדפן או טלפון לא ניגש אליו ישירות (RLS פעיל ללא policies).
- **Cloudflare Worker** = המתווך: עונה לימות בפרוטוקול מודול ה-API, חושף REST לממשקים, ומגיש את דפי ה-HTML.
- **דפי HTML** = ניהול מלא, שולחן שליטה, תצוגה חיה לקהל, ועמדת שופט.

## ✨ יכולות

| תחום | פירוט |
|---|---|
| הצבעה טלפונית | הקראת שאלה ואפשרויות ב-TTS, קליטת הקשה (רק ספרות חוקיות), מניעת הצבעה כפולה, תמיכה בחסויים |
| תוצאות חיות | דף צפייה עם עמודות אחוזים מונפשות, מונה קולות, טיימר מסונכרן-שרת, ציוני שופטים, חשיפת תשובה נכונה, קונפטי |
| שופטים | זיהוי אוטומטי לפי מספר מחייג, **טווח אחוזים אישי מוגדר מראש** שנאכף גם בטלפון וגם בממשק הרשת, שקלול קהל/שופטים לכל שאלה (למשל 70/30) |
| הארכת זמן | מהטלפון (שופט מורשה), משולחן השליטה או מעמדת השופט — חל מיידית על **כלל המשתמשים** |
| סקרים | קבוצת שאלות ברצף בשיחה אחת (`survey_group`) |
| שמות בזמן אמת | שינוי שמות מתמודדים ומשתתפים מהממשק — מיידי בתצוגה ובטלפון |
| שליטה ↔ תצוגה | דף השליטה פותח את התצוגה בחלונית ומדבר איתה **ישירות** (BroadcastChannel + גיבוי localStorage): הודעות ענק, קונפטי, הכרזת מנצח, ערכת נושא, זום, שינוי שם מקומי |
| ניהול מלא | הכל מוגדר מהדפדפן: שאלות, אפשרויות, צבעים, טקסטים של כל הודעה טלפונית, שופטים, משתתפים, ייצוא CSV, הדמיית הצבעות |
| עומסים גדולים | Worker חסר-מצב (stateless), מטמון קצר-מועד, אגרגציה בצד המסד (RPC), אינדקסים — בנוי לאלפי שיחות במקביל |

## 🚀 התקנה (חד-פעמית, ~10 דקות)

### שלב 1: Supabase

1. צרו פרויקט ב-[supabase.com](https://supabase.com) (חינם).
2. פתחו **SQL Editor** → הדביקו את כל התוכן של [`supabase/schema.sql`](supabase/schema.sql) → **Run**.
3. שמרו בצד: **Project URL** (`https://xxxx.supabase.co`) ואת מפתח **service_role** (Settings → API). זו "ההרשאה החד-פעמית" — היא תישמר רק ב-Cloudflare.

### שלב 2: Cloudflare Worker

```bash
cd trivia-system
npm install
npx wrangler login                       # התחברות חד-פעמית
npx wrangler secret put SUPABASE_URL         # הדביקו את ה-Project URL
npx wrangler secret put SUPABASE_SERVICE_KEY # הדביקו את מפתח service_role
npx wrangler secret put ADMIN_TOKEN          # המציאו סיסמת ניהול חזקה
npx wrangler deploy
```

בסיום תקבלו כתובת כמו `https://trivia-ivr.xxxx.workers.dev` — זו הכתובת של **הכל**: הממשקים וה-IVR.

> דפי הממשקים מוטמעים בתוך ה-Worker עצמו (נבנים אוטומטית מ-`public/` ע"י `scripts/build-pages.js` לפני כל `deploy`), כך שהפריסה היא קובץ אחד ואין תלות בהגדרת assets. אם שיניתם דף HTML — הפריסה הבאה תכלול אותו אוטומטית.

> **רוצים לפרוס לוורקר בשם אחר?** שנו את השורה `name = "trivia-ivr"` בקובץ `wrangler.toml` לשם הרצוי (למשל שם של וורקר קיים שכבר חיברתם לימות), והריצו שוב `npx wrangler deploy`.

### שלב 3: ימות המשיח

בשלוחה הרצויה הגדירו קובץ `ext.ini`:

```ini
type=api
api_link=https://trivia-ivr.xxxx.workers.dev/ivr
api_hangup_send=no
```

זהו. חייגו לשלוחה — המערכת חיה.

> המערכת עונה לימות בפרוטוקול הרשמי של מודול ה-API: פקודות `read=` (מצבי הקשה/דיבור/הקלטה), `id_list_message=`, `go_to_folder=hangup`, עם סינון אוטומטי של תווים שאסורים ב-TTS (נקודה, מקף, גרשיים, אמפרסנד...). ניתן לעבוד גם ב-`api_url_post=yes` — שני המצבים נתמכים.

## 🖥️ הממשקים

| כתובת | תפקיד |
|---|---|
| `/` | דף בית עם קישורים לכל הממשקים |
| `/admin.html` | **ניהול** — שאלות, שופטים, משתתפים, כל הטקסטים וההגדרות (דורש ADMIN_TOKEN) |
| `/control.html` | **שולחן שליטה** — פותח את התצוגה בחלונית, הצג/הסתר תוצאות, הארכות, שאלה הבאה, אפקטים, שינוי שמות (דורש ADMIN_TOKEN) |
| `/display.html` | **תצוגה חיה** — מסך מלא לקהל/מקרן, מתעדכן כל שנייה |
| `/judge.html` | **עמדת שופט** — כניסה בטלפון + קוד, סליידרים נעולים לטווח האישי |

### זרימת עבודה מומלצת לערב הצבעות

1. ב-`admin.html`: צרו שאלות עם אפשרויות וצבעים, הגדירו שופטים (טלפון, טווח, קוד), כווננו את שקלול השופטים פר שאלה.
2. ב-`control.html`: לחצו "פתח חלון תצוגה" וגררו למקרן.
3. הפעילו שאלה (▶) — הקהל מחייג ומצביע, התוצאות זזות בשידור חי.
4. שופטים מזינים ציונים מהטלפון (תפריט אוטומטי) או מ-`judge.html`.
5. צריך עוד זמן? +30 שניות בלחיצה (או שהשופט מקיש מהטלפון).
6. בסיום: "חשוף תשובה נכונה" / "הכרזת מנצח" + קונפטי 🎉.

## 📱 מבנה השיחה הטלפונית

**מחייג רגיל:** ברכה → הקראת השאלה והאפשרויות → הקשה → אישור + הקראת תוצאות עדכניות (ניתן לכיבוי) → סיום.

**שופט (מזוהה לפי מספר):**
- `1` הצבעה רגילה
- `2` מתן ציון: בחירת מתמודד → הקשת ציון (נבדק מול הטווח האישי; ציון מחוץ לטווח נדחה ומתבקש שוב)
- `3` הארכת זמן בשניות לכלל המשתמשים (אם מורשה)
- `4` תפריט ניהול: סגירת הצבעה / הפעלת השאלה הבאה / שמיעת מצב תוצאות (אם מורשה)

**סקר:** המחייג עונה שאלה-אחרי-שאלה באותה שיחה.

## 🧮 נוסחת השקלול

לכל אפשרות: `ציון סופי = אחוז קהל × (100−W)/100 + ממוצע ציוני שופטים × W/100`

כאשר `W` = "שקלול שופטים" של השאלה (0 = קהל בלבד). ציון כל שופט חייב להיות בטווח `min_percent`–`max_percent` שהוגדר לו מראש — נאכף בשרת, בטלפון ובממשק.

## ⚙️ איך זה עומד בעומס?

- **Worker חסר-מצב** — כל בקשה עצמאית; ימות שולחת את כל הערכים שנצברו בשיחה, כך שאין זיכרון שיחות בשרת ואין צוואר בקבוק.
- **מטמון קצר** — הגדרות והשאלה הפעילה נשמרות בזיכרון ל-1.5-2 שניות; דף הצפייה מקבל תשובה מהמטמון (שנייה אחת) גם עם מאות צופים.
- **אגרגציה במסד** — ספירת קולות נעשית ב-SQL (`vote_counts` RPC), לא במשיכת שורות.
- **UNIQUE(question_id, phone)** — מניעת כפילויות ברמת המסד, גם תחת מרוץ.
- Cloudflare Workers מתרחב אוטומטית לאלפי בקשות במקביל; Supabase החינמי מספיק לאלפי מצביעים.

## 🔐 אבטחה

- מפתח ה-service_role חי רק כ-Secret ב-Cloudflare (הרשאה חד-פעמית שלכם).
- RLS פעיל על כל הטבלאות ללא policies — גישה ישירה ל-Supabase חסומה.
- ממשקי ניהול/שליטה דורשים `ADMIN_TOKEN` (השוואה בזמן קבוע); שופטים מזוהים בטלפון+קוד.
- דף התצוגה חושף רק נתונים ציבוריים (בלי מספרי טלפון).
