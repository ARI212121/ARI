## 3. המשימות (בצע לפי הסדר)

### משימה א' — פריסת השרת ב-Render
1. פתח https://dashboard.render.com — המשתמש נרשם/מתחבר, מומלץ **Sign up with GitHub**.
2. **New +** ➜ **Blueprint** ➜ בחר את הריפו `ARI212121/ARI`.
   - אם הריפו לא מופיע: *Configure account* ➜ תן ל-Render הרשאה לריפו.
3. Render יזהה את `render.yaml` ויראה שירות בשם `yemot-transcription` (plan: free). אשר יצירה.
4. **חלופה ידנית** (אם Blueprint לא עובד): New ➜ **Web Service** ➜ בחר את הריפו ➜
   - Root Directory: `transcription-server`
   - Build Command: `pip install -r requirements.txt`
   - Start Command: `gunicorn app:app --timeout 120 --workers 1`
   - Instance Type: **Free**
5. המתן לסיום ה-build (1–3 דק'). שמור את כתובת השרת שמתקבלת, למשל
   `https://yemot-transcription.onrender.com`.

### משימה ב' — משתני סביבה ב-Render
בשירות ➜ לשונית **Environment** ➜ הוסף (המשתמש מקליד את הטוקן בעצמו):

| שם | ערך | חובה? |
|----|-----|-------|
| `YEMOT_TOKEN` | `מספר-מערכת:סיסמה` | ✅ |
| `YEMOT_OUTPUT_PATH` | לאן לשמור את הטקסט, למשל `ivr2:/5/000.tts` | ✅ מומלץ |
| `YEMOT_REC_FOLDER` | תיקיית ההקלטות, למשל `ivr2:/4` | אופציונלי |
| `YEMOT_NEXT_EXT` | לאן לעבור אחרי התמלול, למשל `/6` | אופציונלי |
| `YEMOT_LANG` | שפה, ברירת מחדל `he-IL` | אופציונלי |

שמור — Render יפעיל מחדש. **בדיקה:** פתח את כתובת השרת בדפדפן; צריך להופיע
`Yemot transcription server is running.`

### משימה ג' — keep-alive (שהשרת לא יירדם)
בגיטהאב: **Settings ➜ Secrets and variables ➜ Actions ➜ Variables ➜ New repository variable**
- שם: `RENDER_URL` | ערך: כתובת השרת מ-Render.

ה-Action `keepalive.yml` כבר בריפו ורץ כל 10 דקות. אפשר לוודא בלשונית **Actions**
(או להריץ ידנית *Run workflow*).

> חלופה בלי גיטהאב: cron-job.org או uptimerobot.com — הדבק את כתובת השרת, בדיקה כל 10 דק'.

### משימה ד' — הגדרת השלוחה בימות
1. **שלוחת הקלטה** (למשל `4`): מקליטה את המתקשר, שומרת ל-`ivr2:/4/`, "המשך לשלוחה" ➜ `5`.
2. **שלוחת API** (למשל `5`), מסוג API, כתובת:
   ```
   https://<כתובת-השרת>.onrender.com/transcribe
   ```
   **איך השרת יודע איזה קובץ:** או להגדיר `YEMOT_REC_FOLDER=ivr2:/4` (השרת ימצא
   את הקובץ העדכני), או להעביר במפורש `?path=ivr2:/4/000.wav` בכתובת ה-API.

> הערה: שמות השדות המדויקים בממשק ימות עשויים להשתנות בין גרסאות. אם אינך בטוח —
> שאל את המשתמש מה הוא רואה בפאנל, או בדוק בתיעוד של ימות. פורמט התשובות של השרת
> (למטה) יציב.

### משימה ה' — בדיקה מקצה לקצה
בדיקת תמלול בלי ימות (החלף בנתיב קובץ אמיתי אצל המשתמש):
```
https://<כתובת-השרת>.onrender.com/transcribe?path=ivr2:/4/000.wav&format=json
```
תשובה תקינה: `{"ok": true, "text": "...", "note": ""}`.
לאחר מכן — התקשרו לשלוחה, הקליטו, וודאו שהתמלול מוקרא ונשמר.

## 4. פרטים טכניים (עזר)

### API של ימות המשיח (בסיס `https://www.call2all.co.il/ym/api`)
- **הורדה:** `GET /DownloadFile?token=USER:PASS&path=ivr2:/4/000.wav` → בייטים של הקובץ.
- **העלאת טקסט:** `POST /UploadTextFile` עם `token`, `what=ivr2:/5/000.tts`, `contents=<טקסט>`.
  (סיומת `.tts` = ימות מקריא ב-TTS.)
- **רשימת קבצים:** `GET /GetIVR2Dir?token=USER:PASS&path=ivr2:/4` (השרת משתמש בזה
  כדי למצוא את הקובץ העדכני כשלא נשלח `path`).

### פורמט תשובת השרת לימות
- `id_list_message=t-<טקסט>.` → הקראת הטקסט למתקשר.
- אם מוגדר `YEMOT_NEXT_EXT` → מתווסף `go_to_folder=<ext>` למעבר אוטומטי.

### פרמטרים שהנתיב `/transcribe` מקבל
`path` (נתיב הקובץ), `save_to` (יעד שמירה, ברירת מחדל `YEMOT_OUTPUT_PATH`),
`lang` (ברירת מחדל `he-IL`), `format` (`yemot` ברירת מחדל, או `json` לבדיקות).

## 5. שיפור אופציונלי — לולאת אישור אינטראקטיבית
המדריך המקורי תיאר: "השמע תמלול ➜ שאל אם תקין ➜ אם לא, הקלט שוב". כרגע השרת
מקריא ושומר, והלולאה מוגדרת בצד ימות. אם המשתמש רוצה שהשרת עצמו ינהל את ה-
"הקש 1 לאישור / 2 להקלטה חוזרת" (עם פקודת `read` של ימות) — אפשר להוסיף זאת ל-
`app.py`. **חשוב לבדוק זאת מול מערכת ימות חיה** לפני שמסתמכים עליו, כי שגיאה בפקודת
ימות עלולה לשבור את השלוחה למתקשרים. הצע זאת רק אחרי שהזרימה הבסיסית עובדת.
