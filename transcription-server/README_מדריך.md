# מערכת תמלול לימות המשיח – מדריך מלא

מערכת שמתמללת הקלטות מימות המשיח, שומרת את הטקסט חזרה למערכת, ומקריאה
אותו למשתמש – **ללא עלות יחידות**. התמלול רץ במנוע של גוגל (`recognize_google`),
מהיר (שניות בודדות) ותומך בעברית.

השרת רץ על **Render** (אירוח פייתון חינמי), הקוד יושב ב-**GitHub**, ו-**GitHub
Action** שומר על השרת "ער" כדי שלא יירדם.

```
מתקשר מקליט בימות ─▶ ימות קורא לשרת Render עם נתיב הקובץ
                          │
                          ▼
        הורדת הקובץ (DownloadFile)  ─▶  תמלול (recognize_google)
                          │
                          ▼
        שמירת הטקסט חזרה לימות (UploadTextFile, קובץ .tts)
                          │
                          ▼
              ימות מקריא את התמלול למתקשר
```

---

## מה יש בתיקייה הזו

| קובץ | תפקיד |
|------|-------|
| `app.py` | קוד השרת (Flask + SpeechRecognition) |
| `requirements.txt` | רשימת הספריות שיותקנו ב-Render |
| `Dockerfile` | **אופציונלי** – רק אם צריך ffmpeg להמרת פורמט |
| `../render.yaml` | הגדרת פריסה אוטומטית ל-Render (בשורש הריפו) |
| `../.github/workflows/keepalive.yml` | ה-Action ששומר את השרת ער כל 10 דקות |

## שלב 1 – השגת טוקן של ימות המשיח

הטוקן הוא בסך הכל **מספר המערכת + הסיסמה**, מחוברים בנקודתיים:

```
מספר-מערכת:סיסמה
```

לדוגמה, אם מספר המערכת הוא `0733181234` והסיסמה `1234`, הטוקן הוא:

```
0733181234:1234
```

> את הטוקן הזה **לא כותבים בקוד**. מזינים אותו רק בלוח הבקרה של Render (שלב 3),
> כך שהוא נשאר סודי.

---

## שלב 2 – פריסת השרת ב-Render

1. היכנס ל-<https://dashboard.render.com> והירשם (מומלץ עם חשבון GitHub).
2. לחץ **New +** ➜ **Blueprint**.
3. חבר את הריפו הזה (`ARI212121/ARI`). Render יזהה אוטומטית את `render.yaml`.
4. אשר את היצירה. Render יתחיל לבנות את השרת (לוקח 1–3 דקות).

> **חלופה ידנית (בלי Blueprint):** New ➜ **Web Service** ➜ בחר את הריפו ➜
> הגדר:
> - **Root Directory:** `transcription-server`
> - **Build Command:** `pip install -r requirements.txt`
> - **Start Command:** `gunicorn app:app --timeout 120 --workers 1`
> - **Instance Type:** `Free`

בסיום תקבל כתובת כמו:
```
https://yemot-transcription.onrender.com
```
**שמור את הכתובת הזו** – נשתמש בה בשלבים הבאים.

## שלב 3 – הגדרת משתני הסביבה (Environment Variables) ב-Render

בלוח הבקרה של השירות ➜ לשונית **Environment** ➜ הוסף:

| שם המשתנה | ערך | חובה? |
|-----------|-----|-------|
| `YEMOT_TOKEN` | `מספר-מערכת:סיסמה` (מהשלב הראשון) | ✅ חובה |
| `YEMOT_OUTPUT_PATH` | לאן לשמור את הטקסט, למשל `ivr2:/5/000.tts` | ✅ מומלץ |
| `YEMOT_REC_FOLDER` | תיקיית ההקלטות, למשל `ivr2:/4` | אופציונלי |
| `YEMOT_NEXT_EXT` | לאן לעבור אחרי התמלול, למשל `/6` | אופציונלי |
| `YEMOT_LANG` | שפת תמלול, ברירת מחדל `he-IL` | אופציונלי |

לאחר השמירה Render יפעיל את השרת מחדש עם ההגדרות.

**בדיקה מהירה:** פתח בדפדפן את כתובת השרת. אם מופיע
`Yemot transcription server is running.` – השרת חי. 🎉

## שלב 4 – שמירה על השרת "ער" (keep-alive)

השרת החינמי של Render **נרדם אחרי 15 דקות** ללא פעילות, וההתעוררות אורכת
~50 שניות. ה-GitHub Action שכבר נמצא בריפו (`keepalive.yml`) פותר את זה –
הוא שולח "פינג" כל 10 דקות מהענן של גיטהאב (בלי מחשב פתוח).

**הגדרה חד-פעמית:**
1. בריפו בגיטהאב: **Settings** ➜ **Secrets and variables** ➜ **Actions** ➜
   לשונית **Variables** ➜ **New repository variable**.
2. שם: `RENDER_URL` | ערך: כתובת השרת שלך (למשל `https://yemot-transcription.onrender.com`).
3. זהו. אפשר לוודא בלשונית **Actions** שה-workflow רץ (או להריץ ידנית עם *Run workflow*).

> **חלופה בלי גיטהאב:** אתר חינמי כמו <https://cron-job.org> או
> <https://uptimerobot.com> – הדבק את כתובת השרת והגדר בדיקה כל 10 דקות.

> ⚠️ **שים לב למכסה:** ל-Render יש כ-750 שעות חינם בחודש לכל חשבון. שירות אחד
> שרץ תמיד מנצל כמעט את כולן. אם תרצה כמה שרתים כאלה – פתח חשבון נפרד לכל אחד.

## שלב 5 – הגדרת השלוחה בימות המשיח

הרעיון: שלוחת **הקלטה** מקליטה את המשתמש, ואז שלוחת **API** קוראת לשרת שלנו.

### 5א. שלוחת הקלטה
צור שלוחה מסוג הקלטה (למשל שלוחה `4`) שמקליטה את המשתמש ושומרת את הקובץ
בתיקייה שלה (`ivr2:/4/`). הגדר "המשך לשלוחה" ➜ שלוחת ה-API (למשל `5`).

### 5ב. שלוחת API
צור שלוחה (למשל `5`) מסוג **API**. בכתובת ה-API הזן את כתובת השרת + הנתיב `/transcribe`:

```
https://yemot-transcription.onrender.com/transcribe
```

**כיצד השרת יודע איזה קובץ לתמלל?** שתי אפשרויות:

- **אפשרות א' (מומלץ – פשוט):** הגדר במשתנה `YEMOT_REC_FOLDER` את תיקיית ההקלטות
  (`ivr2:/4`). השרת ימצא לבד את הקובץ העדכני ביותר בתיקייה ויתמלל אותו. אין צורך
  להעביר פרמטרים.

- **אפשרות ב' (מדויק):** העבר את הנתיב במפורש בכתובת ה-API:
  ```
  https://yemot-transcription.onrender.com/transcribe?path=ivr2:/4/000.wav
  ```
  (שנה את שם הקובץ לפי איך שההקלטה נשמרת אצלך.)

### מה השרת מחזיר לימות
השרת עונה בפקודת ימות שמקריאה את התמלול למשתמש:
```
id_list_message=t-<הטקסט המתומלל>.
```
ואם הגדרת `YEMOT_NEXT_EXT` – ימות יעבור אוטומטית לשלוחה הזו אחרי ההקראה
(שם אפשר לשאול "האם התמלול תקין? הקש 1 לאישור, 2 להקלטה חוזרת").

במקביל, הטקסט **נשמר** בקובץ שהגדרת ב-`YEMOT_OUTPUT_PATH` (עם סיומת `.tts`),
כך שהוא זמין במערכת ויוקרא בכל כניסה לשלוחה הזו.

## שלב 6 – בדיקה

בלי ימות בכלל, אפשר לבדוק שהתמלול עובד: קרא לשרת עם קובץ קיים במערכת שלך
ובקש פלט JSON:
```
https://yemot-transcription.onrender.com/transcribe?path=ivr2:/4/000.wav&format=json
```


## נתונים טכניים ומגבלות

- **מהירות תמלול:** ~2–8 שניות לדקת הקלטה (רוב הזמן זה ההורדה/העלאה, לא התמלול).
  אם השרת היה רדום – הוסף ~50 שניות להתעוררות הראשונה.
- **פורמט קבצים:** ימות שומר הקלטות ב-WAV, שהשרת קורא ישירות. אם אצלך הפורמט
  שונה וההמרה נכשלת – עבור ל-Runtime = Docker ב-Render (ה-`Dockerfile` כבר מוכן
  ומתקין `ffmpeg`).
- **מנוע התמלול:** `recognize_google` הוא endpoint לא-רשמי של גוגל שמיועד
  לשימוש קל. הוא חינם ומהיר, אך לא מובטח ליציבות בנפחים גדולים מאוד. לשימוש
  אישי/קהילתי הוא מצוין.
- **עלות משאבים:** השרת עצמו כמעט לא עובד קשה (התמלול קורה בענן של גוגל), אז
  ה-Free tier של Render מספיק בקלות.

|-------|--------------------|

## הערה על "הסתרת מילים"

ביקשת להסתיר מילים כמו קריאה-לשירות-חיצוני ו-Drive. אלו פקודות של **גוגל
סקריפט** בלבד (`UrlFetchApp`, `DriveApp`). בפתרון הזה (פייתון על Render) הן
**כלל אינן קיימות** – קוראים לימות דרך ספריית `requests` רגילה. לכן אין כאן
שום מילה שצריך להסתיר, והבעיה מתייתרת לחלוטין.
